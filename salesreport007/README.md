# SalesReport007 — รายงานขายประจำวัน (สเปก v5)

**หลัก:** รายงานเกิดจากเอกสารที่พนักงานคีย์ใน Express ตามเดิมทุกอย่าง — **IV · AI · ลดหนี้ (SR) · RE**
ระบบดึงมาเรียงเป็นรายงานเอง พนักงานไม่ต้องคีย์ยอดขายหรือเลือกช่องทางซ้ำ ในรายงานพนักงานกรอกแค่ **รายจ่ายประจำวัน + เงินสดนับได้**
ช่วงทดลอง Finny ตรวจคู่กับฟอร์ม Excel เดิมทุกวัน (ฟอร์มเดิมยังเป็นตัวจริงจนกว่า ผบ. สั่งเลิก)

**A. รับเงิน/ลดหนี้** (คอลัมน์ A–H · ระบบเติมจาก Express · แก้ไม่ได้)

| กลุ่ม | เลขเอกสาร | วันที่เอกสาร | ประเภท | ลูกค้า | ยอดเอกสาร | ช่องทาง (จาก Express) | หมายเหตุ |
|---|---|---|---|---|---|---|---|
| ยกมา / วันนี้ | RE/AI/SR/HS | | | | | เงินสด · โอน · เช็ค · ผสม (เงินสด+โอน) · ลดหนี้ (ไม่กระทบเงินสด) · ⚠️ ไม่ระบุช่องทางใน Express | HS → แจ้ง ผบ. · ⚠️ → แก้ RE ใน Express |

ไม่โชว์ยอดเงินสด/โอนรายใบ และไม่มียอดรวมใด ๆ ในแท็บพนักงาน (กติกา "นับก่อน เห็นทีหลัง")

**B. รายจ่ายประจำวัน** (คอลัมน์ J–O · 25 แถว · พนักงานกรอก) — ตารางเดียวที่พนักงานต้องลงเอง

| หมวด (เลือก) | รายการ | จ่ายให้ (ร้าน/คน) | จำนวนเงิน | เลขที่บิล/ใบเสร็จ | ชื่อไฟล์รูปบิล |
|---|---|---|---|---|---|
| น้ำมัน/ค่าเดินทาง | เติมน้ำมันรถส่งของ | ปตท. | 120.00 | INV-889 | 691003_1.jpg |

- หมวดเริ่มต้น: น้ำมัน/ค่าเดินทาง · ค่าขนส่ง/ค่าส่งของ · ค่าแรงรายวัน · อาหาร/น้ำดื่ม · วัสดุสิ้นเปลือง/อุปกรณ์ · ค่าซ่อมบำรุง · ค่าสาธารณูปโภค · อื่น ๆ (ระบุในรายการ) — แก้ได้ที่ `expense_categories` ใน config.json
- **เฉพาะเงินที่จ่ายออกจากลิ้นชักเงินสด** (จ่ายโอนจากบัญชีบริษัทไม่ต้องลง)
- บังคับ หมวด + รายการ + จำนวนเงิน > 0 · **ไม่มีรูปบิล หรือชื่อไฟล์ไม่มีจริงในโฟลเดอร์รูปบิลของสาขา = ไม่นับ** ส่วนต่างตกเป็นเงินขาด
- รูปบิลอัปโหลดเข้าโฟลเดอร์ Drive ของสาขา ชื่อไฟล์ขึ้นต้นด้วย YYMMDD (เช่น `691003_1.jpg`)
- จ่ายหลังนับเงิน 16:30 → ลงในแท็บวันถัดไป

**C. ขายเชื่อวันนี้ (IV)** (คอลัมน์ Q–T · ดูอย่างเดียว): เลข IV · ลูกค้า · ยอด · สถานะ ค้างรับ/รับแล้ว

## สูตร (ฝั่ง CTO/Finny เท่านั้น · `engine/calc.py` = `computeSummary()` ใน Code.gs ตรงกันทุกสตางค์)

```
รับเงินสด      = Σ ยอดเงินสด ใน RE/AI/HS ของรอบ (ยอดตามช่องทางใน RE — หักลดหนี้แล้ว)
รับโอน/QR     = Σ ยอดโอน   ใน RE/AI/HS ของรอบ            (เช็ค · อื่น ๆ แยกช่อง)
คืนเงินสด      = Σ ยอดเงินสด ใน SR ของรอบ (ลดหนี้ที่หักใน RE = 0)
เงินสดที่ควรมี  = float + รับเงินสด − คืนเงินสด − รายจ่ายประจำวัน (ที่มีรูปบิล)
ส่วนต่าง       = เงินสดนับจริง − เงินสดที่ควรมี        ← เผยให้พนักงานเห็นหลังส่งเท่านั้น
ยอดนำฝาก      = เงินสดนับจริง − float
```
RE/AI ที่ไม่ระบุช่องทางใน Express จะไม่ถูกนับเข้าเงินสดหรือโอน และขึ้นในคอลัมน์ "ไม่ระบุช่องทางใน Express" ของไฟล์สรุป ให้สาขาไปแก้ RE

**รอบเวลา (เหมือน v4):** ยอดขายคิดตามวัน เงินสดคิดตามรอบ · ตัดรอบ 16:30 แล้วนับเงินทันที · เอกสารหลัง 16:30 ไปเป็น **เอกสารยกมา** ของรายงานวันทำการถัดไปเอง (หาจากผลต่าง ไม่ใช้เวลาในเอกสาร)


## ติดตั้ง (CTO)

1. **Mac mini:** `bash salesreport007/engine/launchd/install_macmini.sh` → ต้องขึ้น `PRE-FLIGHT OK`
2. **Step 0 — ต้องผ่านก่อนเปิดใช้:**
   - `salesreport.py inspect` เทียบยอด IV/AI/SR/RE ของเมื่อวานกับฟอร์มเดิม → RE อยู่ ARTRN หรือ ARRCPT · DOCSTAT ยกเลิก = `C` จริงไหม
   - `salesreport.py inspect-pay` → ดูฟิลด์ตัวเลขของ RE/AI แต่ละใบ เทียบกับใบที่รู้ว่ารับเงินสด/โอน แล้วใส่ชื่อฟิลด์จริงใน `sources.json` → `pay` (ตอนนี้เป็นชื่อที่เดาไว้ เช่น CSHAMT/TRNAMT/CHQAMT) — **ถ้า preflight ขึ้น "ไม่เจอฟิลด์ช่องทางรับเงิน" ทุก RE จะเป็น ⚠️**
   - ถ้า Express เก็บช่องทางของ RE ไว้ไฟล์อื่น (เช่น ตารางรายการรับชำระแยก) ให้แจ้ง — ต้องเพิ่มตัวอ่านไฟล์นั้น
   - ใส่รหัสลูกค้าที่เป็นสาขาด้วยกันใน `interbranch_customers`
3. **Drive:** ก๊อป `apps_script/config.example.json` → `AutoExport/sales_report/config.json` ใส่พนักงาน · float · อีเมล ผบ./Finny
   - โฟลเดอร์รูปบิลต่อสาขาอยู่ **นอก** `sales_report` แชร์ให้พนักงานสาขานั้น → ใส่ id ใน `receipt_folder_id`
   - **ห้ามแชร์โฟลเดอร์ `sales_report`** (มี out.json ที่มียอดเงินสดที่ควรมี)
4. **Apps Script** (บัญชี 007skn0777): โปรเจกต์ใหม่ → วาง `Code.gs` + `appsscript.json` → Script Property `ROOT_FOLDER_ID` = id โฟลเดอร์ `sales_report` → รัน `setup()`
   - `runNow()` เติมแท็บทันที · `finalizeNow()` ล็อก+สรุปทุกสาขาทันที
   - ถ้าติดตั้ง v4 ไปแล้ว: วาง Code.gs ใหม่ทับ แล้วรัน `setup()` อีกครั้ง (ไฟล์เดือนนี้ที่สร้างไว้แล้วยังใช้ต่อได้ แต่แท็บที่สร้างด้วย v4 มีผังเก่า — ลบแท็บวันนี้ทิ้งแล้วรอรอบถัดไปสร้างใหม่)
5. ทดสอบ: `salesreport.py export ready --branch SKN` → `runNow()` → เปิดไฟล์ใน `_sheets/SKN`

**ขั้นต่ำถ้า Apps Script ยังไม่พร้อม:** ทุกรอบ export เขียน `YYMMDD_new_HHMM.csv` (แถวใหม่ พร้อมช่องทางและยอดเงินสด/โอนจาก Express) ไว้ข้าง in.json

## ข้อจำกัดที่ต้องรู้
- **ชื่อฟิลด์ช่องทางรับเงินใน Express ยังเป็นการเดา** (เครื่องที่เขียนโค้ดเปิด DBF จริงไม่ได้) — ต้องผ่าน `inspect-pay` ก่อน
- Drive sync จากสาขาล่าช้าได้: บิลก่อน 16:30 ไม่กี่นาทีอาจตกไปเป็นเอกสารยกมาของวันถัดไป แต่เงินถูกนับแล้ว → ส่วนต่างวันนี้บวก/พรุ่งนี้ลบเท่ากัน (`reconcile` แสดงให้เห็น)
- RE ที่แก้ช่องทางหลังตัดรอบ: รายงานใช้ค่า ณ ตัดรอบ · `reconcile` จับได้ว่าไม่ตรง Express
- Apps Script ทดสอบกับ mock เท่านั้น ยังไม่ได้รันบน Google จริง
- แท็บล็อกด้วย trigger 5 นาที: ล็อกจริงภายใน 16:55–17:00 (แก้หลัง 16:55 ถูกคืนค่าทันที)
- เรื่องรอ ผบ.: ตัดรอบ 16:30 ทั้ง 3 สาขา · float ต่อสาขา · คะแนนคนคีย์ — เวลา/float แก้ใน config.json (เปลี่ยนเวลาตัดรอบต้องแก้ plist + `ROUND_SPLIT` ด้วย)
