# Sales007 — รายงานขายประจำวันแบบ live (salesreport007 v6)

**หลัก:** พนักงานทำงานใน Express ตามเดิมทุกอย่าง (IV · AI · ลดหนี้ · รับชำระ/วางบิลต้องออก RE ทันที)
เอกสารขึ้นแอปภายใน 1–2 นาที → **RE/AI ขึ้นมาให้กดเลือก 💵 เงินสด · 🏦 เงินโอน · 📱 QR Code** → ลงรายจ่ายประจำวัน → 16:30 นับเงิน → ส่ง
ช่วงทดลอง Finny ตรวจคู่กับฟอร์ม Excel เดิมทุกวัน (ฟอร์มเดิมยังเป็นตัวจริงจนกว่า ผบ. สั่งเลิก)

```
เครื่องสาขา (Task Scheduler ทุก 1 นาที)          Vercel (project เดียวกับแอปผลิต)                  พนักงาน / ผบ. / Finny
 sales_push.py ── อ่าน DBF Express ตรง ──▶  /api/sales/push (X-Sales-Token) ──▶ Supabase sales_*      production.007metals.com/sales007
   ARTRN · ARRCPT · ARRCPIT · ARMAS          /api/sales/day · act · audit  ◀──────────────────────  ล็อกอินกลาง (app.007metals.com)
                                             /api/sales/cron (16:56 ล็อกที่ไม่ได้ส่ง)
 Mac mini: macmini/pull_out.py ◀── /api/sales/export ── YYMMDD_out.json → AutoExport/sales_report/{BR}/ (Finny อ่านจาก Drive)
```

ทำไมไม่ใช้ Google Sheet ต่อ (v4/v5): ไฟล์จากสาขาขึ้น AutoExport ผ่าน Drive sync ช้าได้ถึง 15 นาที + รอบ export → ไม่ live
v6 อ่าน DBF บนเครื่องสาขาโดยตรงแบบเดียวกับ so_push.py (กระดานผลิตที่ใช้อยู่แล้ว)

## หน้าแอปพนักงาน (มือถือ/คอม · เห็นเฉพาะสาขาตัวเอง)

| ส่วน | มาจาก | พนักงานทำ |
|---|---|---|
| 💰 **รับเงิน / ลดหนี้** — RE · AI · HS · SR ของรอบ | Express (live) | RE/AI/HS: กด **เงินสด / เงินโอน / QR Code** · SR: กด **หักใน RE / คืนเงินสด** · ตัวนับ "เหลือ X ใบ" |
| ⏭️ ออกหลังตัดรอบ 16:30 | Express | เลือกช่องทางไว้ได้เลย · ไปขึ้นรายงานวันถัดไปเป็น "ยกมา" |
| 🧾 **ขายเชื่อวันนี้ (IV)** — live | Express | ดูอย่างเดียว · ค้างรับ → ตัดชำระแล้ว + เลข RE (จาก ARRCPIT) |
| 💸 **รายจ่ายประจำวัน** | พนักงานกรอก | หมวด · รายการ · จ่ายให้ · จำนวนเงิน · เลขที่บิล · **ถ่ายรูปบิล** (ไม่มีรูป = ไม่นับ) |
| 🔐 **ปิดยอด** (เปิดหลัง 16:30) | พนักงานกรอก | เงินสดที่นับได้ → ส่ง (ต้องเลือกช่องทางครบทุกใบ) → เห็น **เฉพาะส่วนต่าง** |

- ไม่มียอดรวมเงินสด/โอน/เงินสดที่ควรมี บนหน้าพนักงาน และไม่มีใน network response ของพนักงาน
- ผู้จัดทำ = คนที่ล็อกอินกดส่ง · ทุกการเลือกช่องทางบันทึกว่าใครเลือกเมื่อไร (`sales_choice_log`)
- หน้าเว็บรีเฟรชเองทุก 20 วินาที (ไม่รีเฟรชระหว่างพิมพ์)
- หมวดรายจ่าย: น้ำมัน/ค่าเดินทาง · ค่าขนส่ง/ค่าส่งของ · ค่าแรงรายวัน · อาหาร/น้ำดื่ม · วัสดุสิ้นเปลือง/อุปกรณ์ · ค่าซ่อมบำรุง · ค่าสาธารณูปโภค · อื่น ๆ (แก้ที่ `EXPENSE_CATEGORIES` ใน `server/sales_api.py`)

## สูตร (`engine/calc.py` · คิดฝั่งเซิร์ฟเวอร์เท่านั้น)
```
รับเงินสด / รับโอน / รับ QR = Σ ยอด RE·AI·HS ตามช่องทางที่เลือก
คืนเงินสด      = Σ ยอด SR ที่เลือก "คืนเงินสด"   (ลดหนี้ที่หักใน RE ไม่กระทบเงินสด)
เงินสดที่ควรมี  = float + รับเงินสด − คืนเงินสด − รายจ่ายประจำวัน (ที่มีรูปบิล)
ส่วนต่าง       = เงินสดนับจริง − เงินสดที่ควรมี        ยอดนำฝาก = เงินสดนับจริง − float
```

## รอบเวลา
- เอกสารรับเงิน/ลดหนี้ที่ **ระบบเห็นครั้งแรก** ก่อน 16:30 และยังไม่อยู่ในรายงานใด = รายงานวันนี้ · หลัง 16:30 = รายงานวันทำการถัดไป (ยกมา)
- แก้เอกสารใน Express หลังเข้าระบบแล้ว ยังอยู่รอบเดิม (ยอดอัปเดตตาม Express จนกว่าจะล็อก)
- ส่งได้ 16:30–16:55 · เลย 16:55 ล็อกอัตโนมัติ (cron 16:56 + ทุกครั้งที่มีคนเปิดแอป) · ล็อกแล้วประทับ `report_date` ให้เอกสารชุดนั้น = หลักฐาน
- วันที่ไม่มีเอกสารและไม่มีรายจ่าย (วันหยุด) ไม่สร้างรายงาน เอกสารไหลไปวันถัดไปเอง

## Finny / ผบ. (แท็บ "ตรวจ" ในแอป · หรือ `YYMMDD_out.json` ใน Drive)
- ยอด Express ตามวันที่เอกสาร **IV / AI / SR / RE / HS** → เทียบฟอร์มเดิม (J63 · แถว 65–73 · 75–82 · C113)
- รับเงินสด · โอน · QR · คืนเงินสด · รายจ่าย · float · เงินสดที่ควรมี (C124) · นับจริง (C125) · ส่วนต่าง · ยอดนำฝาก
- ช่องทางรายใบ (จับคู่ statement โอน/QR) · รูปบิลรายจ่าย (ลิงก์ชั่วคราว 1 ชม.)
- ข้อผิดปกติ: ไม่ได้เลือกช่องทาง · รายจ่ายไม่มีบิล · **เอกสารถูกแก้ยอด/ยกเลิกใน Express หลังล็อก** · เอกสารยกมา · เอกสารหลังตัดรอบ (จำนวน/ยอด)
- เงินสดรายงานใหม่คิดตามรอบ ฟอร์มเดิมคิดทั้งวัน → ต่างกันเท่ากับเงินสดของเอกสารหลังตัดรอบ (วันนี้ลบ เมื่อวานบวก)

## ติดตั้ง (CTO — Claude deploy/รัน SQL/ตั้ง env ให้ไม่ได้)
1. **Supabase กลาง:** รัน `sql/sales007.sql` → ติ๊กสิทธิ์ `sales007` รายคนที่ app.007metals.com/admin/access (พนักงานต้องมีสาขาในทะเบียน `employees.branch`)
2. **Vercel env:** `SALES007_PUSH_TOKEN` (สุ่ม ≥ 32 ตัว: `openssl rand -hex 24`) · `CRON_SECRET` (สุ่ม) · `SALES007_START_DATE` (วันเริ่ม เช่น `2026-10-05`)
   · `SALES007_AUDIT_IDS` (employee id ของ Finny/คนตรวจ ที่ไม่ใช่ admin) · ไม่บังคับ: `SALES007_FLOAT` เช่น `{"BK":0,"SKN":0,"PPS":0}` · `SALES007_CUTOFF` / `SALES007_DEADLINE`
   → deploy (merge branch) · cron ใน `vercel.json` = 09:56 UTC (16:56 น.) — แผน Hobby อาจยิงช้าในชั่วโมงนั้น แต่การเปิดแอปครั้งถัดไปล็อกให้อยู่แล้ว
3. **Step 0 ที่เครื่องสาขา:** `python sales_push.py C:\007\sales_push_SKN.cfg --inspect` → ยอด IV/AI/SR/RE ของเมื่อวานต้องตรงฟอร์มเดิม · ดูว่า RE อยู่ ARTRN หรือ ARRCPT และ "RE ที่รู้ว่าตัด IV ใบไหน" ไม่เป็น 0
   ไม่ตรง → แก้ `SOURCES` / `LINKS` ต้นไฟล์ `sales_push.py` (ชื่อไฟล์/ฟิลด์ยังเป็นการเดาจากโครง Express ที่ so_push ใช้)
4. **เครื่องสาขา (เครื่องเดียวกับ so_push):** ก๊อป `feeder/sales_push.py` + `sales_push.example.cfg` → ใส่ค่า → `--dry` ดูก่อน → Task Scheduler ทุก 1 นาที:
   `schtasks /create /sc minute /mo 1 /tn "007 sales_push SKN" /tr "pythonw C:\007\sales_push.py C:\007\sales_push_SKN.cfg"`
5. **Mac mini (ให้ Finny อ่านจาก Drive):** `SALES007_PUSH_TOKEN=... APPROVE007_ALL_ON_CLOUD=... python3 salesreport007/macmini/pull_out.py` ตั้ง cron/launchd 17:10 และ 08:00
6. เปิด production.007metals.com/sales007 ด้วยบัญชีพนักงาน → ออก RE ทดสอบใน Express → ต้องขึ้นภายใน 1–2 นาที

## ข้อจำกัด / เรื่องที่ต้องยืนยัน
- **ชื่อไฟล์/ฟิลด์ Express ยังเป็นการเดา** (ARRCPT/ARRCPIT/DOCSTAT=C) — ต้องผ่าน `--inspect` ก่อนเปิดใช้
- "live" = feeder ทุก 1 นาที + หน้าเว็บรีเฟรช 20 วินาที → เห็นภายใน ~1–2 นาที · ถ้าเครื่องสาขาปิด/เน็ตหลุด หน้าแอปขึ้นเวลาอัปเดตล่าสุดให้เห็น
- รอบตัดใช้ "เวลาที่ระบบเห็นครั้งแรก" ไม่ใช่เวลาคีย์ใน Express: บิลที่คีย์ 16:29 อาจเข้าระบบ 16:30–16:31 แล้วไปรายงานพรุ่งนี้ (เงินถูกนับวันนี้ → ส่วนต่างวันนี้บวก/พรุ่งนี้ลบ Finny เห็นใน "เอกสารหลังตัดรอบ")
- ยังไม่มีตัวเลือก "ผสม" (จ่ายเงินสดบางส่วน + โอนบางส่วนใน RE ใบเดียว) — ถ้าเกิดบ่อยต้องเพิ่ม
- โค้ด Google Sheet/Apps Script ของ v4–v5 ถูกถอดออก (ยังไม่เคยติดตั้งใช้งาน)
